# Dependency lock for the Phase 2A runtime stack (ADR 0001, Step 0 follow-up).
#
# Pins every runtime dependency (direct + transitive) to an exact version so installs
# are reproducible and the crypto/web stack (bcrypt, cryptography, sqlcipher3-wheels,
# flask) can't silently drift — the class of surprise that the bcrypt 5.0
# silent-truncation -> ValueError change caused earlier in the project.
#
# Provenance: generated from `pip freeze` in CI on ubuntu x64 / Python 3.11 (the
# Phase 2A job), which resolves a superset of the Phase 1 deps. Applied via
# `pip install -r <requirements> -c constraints.txt` in ALL three CI jobs, so the
# SAME locked set is exercised on both Python 3.11 (Phase 2A) and 3.12 (Phase 1).
#
# numpy is pinned to 2.4.6: Python 3.11 resolves 2.4.6 and 3.12 would otherwise pick
# 2.5.0, so 2.4.6 is the shared floor with wheels for both — the Phase 1 ground-truth
# harness in CI confirms the (patch-level) numpy difference doesn't change results.
#
# Regenerate after an intentional dependency bump: re-run the `pip freeze` capture in
# CI (git history has the TEMP steps) and update this file; CI re-validates both jobs.
