# Phase 3 · Increment 3.1 — Migrate-on-login Wiring — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auto-upgrade the encrypted database schema on every login by calling `migrations.migrate()` when a per-request connection is opened, so every later Phase 3 increment can ship a migration that reaches already-installed databases.

**Architecture:** Add one call to the existing, already-merged migration runner (`app/infra/migrations.py`, ADR 0002) inside the per-request connection factory `app.api.guards.get_db()`, immediately after `storage.connect(key)` and before the connection is cached in `g.db`. On an up-to-date database (the common path) `migrate()` is a cheap no-op — one `PRAGMA user_version` read plus comparisons — so behavior is frozen for existing installs. The change makes the ADR-0002 "Defers — migrate-on-login" consequence true.

**Tech Stack:** Python 3.11, Flask (app factory + `g`/`teardown_appcontext`), SQLCipher (`sqlcipher3`), pytest. Vanilla no-build; no new dependencies.

```python
import pytest

from app import create_app
from app.infra import migrations, storage

_LATEST = migrations.MIGRATIONS[-1][0]


@pytest.fixture()
def client(app_data_dir):
    app = create_app()
    app.config.update(TESTING=True)
    c = app.test_client()
    c.post("/api/setup", json={"username": "nadim", "password": "hunter2"})
    return c


def _open_raw(client):
    """A direct SQLCipher connection to the same DB the app uses, via the
    in-memory key setup left in app.config."""
    key = client.application.config["DB_KEY"]
    return storage.connect(key)


def test_login_auto_upgrades_a_v0_database(client):
    # Simulate a pre-versioning install: valid baseline schema, version reset to 0.
    conn = _open_raw(client)
    conn.execute("PRAGMA user_version = 0")
    conn.commit()
    conn.close()

    # Any authenticated request opens a connection via get_db() -> should migrate.
    resp = client.get("/api/datasets")
    assert resp.status_code == 200

    conn = _open_raw(client)
    assert migrations.current_version(conn) == _LATEST
    conn.close()
```

Change `get_db()` from:

```python
def get_db():
    """A per-request SQLCipher connection opened from the in-memory db_key."""
    if "db" not in g:
        key = current_app.config.get("DB_KEY")
        if key is None:
            raise RuntimeError("no database key in session")
        g.db = storage.connect(key)
```

to:

```python
def get_db():
    """A per-request SQLCipher connection opened from the in-memory db_key.

    The connection is run through the migration seam (ADR 0002) before it is
    cached, so an existing database is auto-upgraded on login. On an up-to-date
    database migrate() is a no-op (one PRAGMA read), so behavior is frozen.
    """
    if "db" not in g:
        key = current_app.config.get("DB_KEY")
        if key is None:
            raise RuntimeError("no database key in session")
        conn = storage.connect(key)
        try:
            migrations.migrate(conn)
        except Exception:
            conn.close()
            raise
        g.db = conn
    return g.db
```
