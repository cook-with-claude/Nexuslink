# La Passion — CDR Pattern Detection

[![CI](https://github.com/cook-with-claude/La-Passion/actions/workflows/ci.yml/badge.svg)](https://github.com/cook-with-claude/La-Passion/actions/workflows/ci.yml)

A multi-phase CS portfolio project that infers a person's likely **home**, **work**,
and **frequent** areas from Call Detail Records (CDRs), with the algorithm proven
correct against synthetic data before any product is built on top of it.

> **Synthetic data only.** Every CDR in this repository is generated by code with a
> fixed random seed — no real telecom data, no network access, no LLM ever produces a
> row. This is a deliberate, correctness-first foundation, not a deployed system.

## Why this project is structured the way it is

The hard part of location inference isn't naming the most-called area — it's knowing
*how much to trust* that answer. A handful of calls, a near-tie between two
neighborhoods, or sparse coverage over a long span can all make a confident-looking
guess meaningless. So Phase 1 is dedicated entirely to **proving the detection
algorithm and its confidence model are correct** against a known ground truth, before
any UI, server, or account work is layered on.

### Phase 2A — Backend (desktop app)

A Flask backend behind a PyWebView desktop window, over a SQLCipher-encrypted
SQLite database with single-account auth. The detection algorithm is reused
unchanged via a thin bridge — Phase 1 stays frozen. Run the API tests with
`pytest tests/phase2a`; launch the desktop app with `python main.py`.
See [`docs/superpowers/specs/2026-06-24-phase2a-backend-design.md`](docs/superpowers/specs/2026-06-24-phase2a-backend-design.md).

> **Desktop window prerequisite (Windows).** The PyWebView shell hosts Edge
> WebView2 through .NET, so it needs the **.NET Desktop Runtime** installed
> (`winget install Microsoft.DotNet.DesktopRuntime.8`; on Windows ARM64 use the
> `…DesktopRuntime.8.arm64` package). `main.py` auto-configures pythonnet for
> ARM64 (CoreCLR + the vendored .NET Core WebView2 interop in `vendor/webview2/`);
> on x64 Windows the default path is used. macOS/Linux render via WebKit and need
> no .NET. The Flask API and SPA themselves run in any browser regardless.

### The four-gate confidence model (Phase 1 in one table)

The winner is always the area with the most calls; confidence only says how much to
trust it. Four independent gates are each scored High/Medium/Low, and the result is the
**lowest** of the four — a strong gate never rescues a weak one:

| Gate | Question |
|---|---|
| **N** | Enough calls at all? |
| **Share** | Does the winner dominate? |
| **Closeness** | Is it a near-tie? |
| **Density** | Enough coverage for how long we've watched? |

Ground truth is tallied independently of the code under test, so the validation
actually proves something rather than checking the code against itself.

## How this repo is built — a two-agent + human workflow

This project is developed by **two AI coding agents (Claude Code and Codex)** plus the
humans (Nadim, who merges; Khaled, who runs the suite). The agents can't see each
other's chat, so **git is the only shared memory**: work happens on per-agent branches,
the *other* agent reviews the diff, and only Nadim merges to `main`. The conventions
live in [`COLLAB.md`](COLLAB.md); the running intent log (what changed and *why*) lives
in [`HANDOFF.md`](HANDOFF.md).

CI runs both suites on every push and pull request — the Phase 1 unit tests + validation
harness, and the Phase 2A backend tests (`tests/phase2a`) — so correctness no longer
depends on any one machine being able to run them.

## Quick start

```bash
cd phase1_cdr
python -m venv .venv
# Windows (PowerShell): .venv\Scripts\Activate.ps1   |   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python main.py sample_data.csv ground_truth.json   # validation harness — prints a pass/fail table
pytest tests/                                       # unit tests
```
