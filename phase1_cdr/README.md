# Phase 1 — CDR Pattern Detection (Algorithm Validation)

Phase 1 of a CS portfolio project. The goal is narrow and deliberate: **prove the
pattern-detection algorithm is correct against synthetic data with a known ground
truth**, before any UI, server, or account work in later phases.

## Important: synthetic data only

Every CDR row in this project is **synthetic**, generated by code with a fixed random
seed. No real telecom data and no LLM is ever used to produce rows. None of this code
touches the network, a UI, or an account system — that is by design, not an omission.
`dev_fixtures.py` is a throwaway dev generator and is meant to be deleted once the
team's real (still synthetic) generator exists.

## What it does

- **`loader.py`** — reads a `.csv` / `.xlsx` / `.xls` CDR file into a validated
  DataFrame (6-column schema), dropping rows with bad timestamps or invalid
  `call_type` and warning about them.
- **`detection.py`** — pure functions that infer a user's likely **home** area
  (overnight), **work** area (weekday daytime), and most **frequent** areas, each with
  a confidence label (`High` / `Medium` / `Low` / `Insufficient data`).
- **`dev_fixtures.py`** — deterministically builds `sample_data.csv` and an
  *independently computed* `ground_truth.json` for four test users.
- **`validate.py` / `main.py`** — run the detectors against the ground truth and print
  a pass/fail table.

## Setup

```bash
python -m venv .venv
# Windows (PowerShell):   .venv\Scripts\Activate.ps1
# Windows (Git Bash):     source .venv/Scripts/activate
# macOS / Linux:          source .venv/bin/activate
pip install -r requirements.txt
```

## Usage

Regenerate the fixtures (deterministic — identical output every run):

```bash
python dev_fixtures.py
```

Run the validation harness (prints a table, exits non-zero if anything fails):

```bash
python main.py sample_data.csv ground_truth.json
```

Run the unit tests:

```bash
pytest tests/
```

## The four test users

| User | Pattern | Home expectation | Work expectation |
|---|---|---|---|
| A | Consistent | exact area, `High` | exact area, `High` |
| B | Noisy, real plurality | exact area, ≤ `Medium` | exact area, ≤ `Medium` |
| C | Sparse (3 records) | none, ≤ `Low` | none, ≤ `Low` |
| D | Adversarial / no stable pattern | none, ≤ `Medium` | none, ≤ `Low` |

User D is the real stress test: the algorithm must **resist** calling a near-coin-flip
or scattered pattern "High confidence."

## Why ground truth is computed independently

`ground_truth.json` is built inside `dev_fixtures.py` by tallying counts in the known
time windows with plain `groupby` — it never imports `detection.py`. If the ground
truth were produced by the function under test, the validation would prove nothing.
